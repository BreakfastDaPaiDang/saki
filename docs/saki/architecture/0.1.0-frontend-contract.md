# Saki 0.1.0 frontend contract

English | [中文](0.1.0-frontend-contract.zh.md)

This reference defines the information, state, navigation, and interaction obligations of the version 0.1.0 Web client. It deliberately does not choose layout, color, typography, density, illustration, motion style, visual hierarchy, or a responsive composition. Concept images may explore those choices without becoming implementation authority, and no requirement here implies that every address appears on one page. The [Web UI integration baseline](0.1.0-web-ui-baseline.md) defines which DSH surfaces remain intact and the small shell additions Saki requires.

## Client boundary

`packages/saki/web-ui` is a DSH client plugin with its browser implementation under `src/client/`. It composes through the existing client Cordis tree, services, stores, and typed slots; React remains a projection of immutable client snapshots. The package may use internal feature domains for Project selection, Work, Changes, Sessions, Attention, Model Supply, and Settings, but remains one package until a domain gains an independent Consumer or release lifecycle.

The browser reads typed Saki Projections and submits Control Intents through `saki-host-api`. It does not call GitHub, model providers, credential stores, system Git, or the filesystem directly. It never retains a Host path as an operation handle, constructs Actor or Grant facts, or infers success from a notification. Existing DSH conversation, Terminal, settings, attachment, and tool-presentation capabilities are embedded through their services and slots rather than copied into Saki components.

The client cache is disposable. A complete Projection response is the only client baseline; `onChanged` and live Host frames invalidate keys and cause a re-query. Reconnect rebuilds affected snapshots. Client state may retain selection, expansion, drafts, and an optimistic overlay, but none of those values becomes product authority.

## View addresses and context

Each navigable state has a typed `SakiViewAddress` built from stable ids rather than paths or display names. An address identifies a destination or selection state, not necessarily a top-level page. Version 0.1.0 must preserve these addresses through Project switching and browser reload; serialization into public shareable URLs is optional until the Web client has a general routing facility.

| Address | Required context and return target |
| --- | --- |
| My Work | Principal-scoped work, pending responses and review results across authorized Projects; each item returns to its Project and source object |
| Projects | Installation and Host health; opens one Development Project |
| Attention | Principal-scoped items across Projects; each item returns to its owning object and Project |
| Work | Project, selected Board or Milestone filter, and optional Work Item |
| Changes | Project and Resource Binding revision; optional file or Diff selection |
| Sessions | Project, Work Session, DSH Session, and optional Agent Run |
| Terminal | Project and current binding; terminal identity remains owned by DSH |
| Project Settings | Project binding, GitHub mapping, Agent Profile, Automation Policy, and synchronization state |
| Model Supply | Installation-level Provider Account Profiles, routes, context policies, and Generation Jobs |

Changing the current Development Project changes Work, Changes, Sessions, Terminal, and Project Settings together. Attention and Model Supply may span Projects, but every mutating affordance names its target Project. A Project switch never discards a draft, optimistic Intent, uncommitted Git state, pending question, or running operation; it either preserves the state under its owning address or asks for a deliberate resolution.

## Product surfaces

Version 0.1.0 adds exactly two top-level Saki pages. Work is the beginner-operable surface: it projects My Work across authorized Projects, uses plain-language groups, shows one next action per item, and hides Git, provider, budget and synchronization details until the user asks for technical details or recovery. It remains a Projection of the same authoritative objects and never weakens Grants or confirmation rules.

Project is the complex surface for one selected Development Project. Its internal destinations are Board, Milestones, Changes, Sessions & Runs, Trace and Project Settings. Only one destination occupies the main content area at a time. Work, Changes, Sessions, Terminal and Project Settings addresses resolve inside Project; selecting a Work Item, Session or Run preserves a return address to the owning section. Principal-scoped Attention resolves to Work, selected-Project automation and Run evidence resolve to Project, and installation-wide Model Supply resolves to Settings.

Session continues to reuse the existing DSH Conversation surface, while Settings remains deployment configuration. They are inherited DSH surfaces rather than additional Saki pages. The existing DSH AppFrame and sidebar also remain the shell. A generic `main.surface` chain slot chooses Work or Project only when its Saki address is active and otherwise renders Conversation. A generic `sidebar.primary.action` list slot lets the Saki plugin add Work and Project entries without replacing the sidebar. The Saki plugin uses existing session-header, conversation-view and settings-section slots for smaller additions.

## Projection set

The first client consumes a small set of complete read models instead of joining backend records in the browser.

| Projection | Required facts |
| --- | --- |
| My Work | Principal-scoped source Project and object, presentation group, Work Item Status, assignment, Run or Intervention summary, one recommended Action Offer, and its reason |
| Project index | Project identity, binding health, attention count, active Runs, GitHub freshness, and automation pause state |
| Development Workspace | Current Project, binding revision and display location, Git summary, primary Work Session, active operations, and blocking recovery |
| Board | Confirmed GitHub Sync Checkpoint, mapped columns and order, Inbox membership, optimistic overlays, filters, and mapping health |
| Work Item detail | Issue facts, acceptance criteria, assignment, Sessions, Agent Runs, Git and PR evidence, CI, interventions, and activity references |
| Changes | HEAD and branch observations, inherited, staged, unstaged and untracked changes, bounded Diff pages, and operation eligibility |
| Session view | Work Session identity, associated DSH Sessions, primary and historical Runs, intervention state, and existing DSH conversation projection |
| Attention Inbox | Source object, severity, target Principal, target Project, required response, age, and return address |
| Automation | Policy revision, enabled actions, hard limits, reservations, settled usage, unknown observations, and pause reasons |
| Model Supply | Profile health, safe authentication state, model routes, Usage Snapshot age, context policy, and generation queue |

A Projection exposes display-safe locations and external URLs only where the Host has authorized them. Credential values, DPAPI ciphertext, GitHub App private material, local operation handles, mutable entities, and unbounded Diff or log bodies never enter these models.

An Action Offer is a Projection fact, not authority. The control plane derives it from the current Work Item Status, Triage Role or Work Assignment, open Intervention Requests, active Dispatch and Run state, the Principal's Grant, Automation Policy, and current binding, Git, synchronization, credential, and budget observations. The client never derives actions from Work Item Status alone. My Work places an item into ready to start, active, waiting for you, or recently finished as presentation groups and returns at most one recommended Action Offer; alternative operations remain in the owning detail view. An item awaiting acceptance remains waiting for you, while a Done or Canceled item never offers acceptance.

Submitting an Action Offer sends a typed Intent with the expected Projection revision. The control plane resolves the current Principal and re-evaluates authority and eligibility before accepting it, so a rendered action cannot authorize stale or otherwise disallowed work. When an expected action is unavailable, My Work returns a plain-language reason and offers a repair or inspection operation only when the Principal may perform it.

## State semantics

Every data-bearing view distinguishes the following conditions without relying on color alone.

| State | Client obligation |
| --- | --- |
| Confirmed | Identify the Projection revision or confirmation time that authorizes the displayed fact |
| Refreshing | Keep the confirmed value readable while indicating that a newer read is pending |
| Optimistic | Identify the pending Intent and preserve the confirmed value needed for rollback or conflict display |
| Stale or offline | Show age and failed source; never describe cached remote data as current |
| Conflict | Show requested and newly confirmed facts and require a new Intent for retry |
| Unavailable | Name the denied capability or dependency and preserve unaffected local functions |
| Repair required | Identify the broken GitHub mapping or Resource Binding and offer only attributed repair operations |
| Reconciliation required | Keep the ambiguous effect visible; do not offer a blind duplicate action |
| Intervention required | Show the durable request, authorized responder, blocking scope, and response status |
| Empty | Explain whether no objects exist, filters removed them, or a source has not completed its first scan |

An accepted Control Intent receives a stable receipt and remains visible until its resulting Projection confirms success, reports failure, conflicts, or requires reconciliation. A transport timeout is not a product failure. The client disables repeated submission while outcome inspection is pending unless the operation explicitly supports another independent Intent.

## Interaction flows

| Flow | Required outcome |
| --- | --- |
| Register Project | Select an existing directory, review resolved Git top level and duplicate or dirty-state evidence, confirm bindings, then open the Development Workspace |
| Move Work Item | Apply an optimistic overlay, perform expected-fingerprint mutation, confirm GitHub state, or show conflict and restore the confirmed card |
| Give to Agent | Display Profile, Model Route, requested permissions, binding health, inherited changes, and applicable limits before manual submission |
| Automatic claim | Show policy, Actor, reservation, Dispatch, Run, and pause evidence without requiring a click or hiding why work started |
| Review and deliver | Inspect bounded Diffs, select files, stage, commit, push, associate PR and CI, and accept or automatically complete only from Outcome Evidence |
| Answer intervention | Open from Attention or the owning object, submit one expected-revision response, and converge on the separately confirmed result |
| Repair binding or mapping | Keep history readable, explain the broken observation, collect explicit replacement selection, and refresh before enabling mutations |
| Use model supply | Authorize a profile, inspect safe health and usage observations, choose a route at a safe boundary, and inspect Generation Jobs and outputs |

Risky operations require confirmation that names the affected Project and resource. This includes Project retirement, binding replacement without strong continuity evidence, takeover of inherited changes, push, automatic merge, automatic Done, credential removal, and budget exception. Ordinary reversible navigation, refresh, filters, and read-only inspection do not require confirmation.

Board drag has a keyboard-equivalent move operation. Every status, progress, conflict, and attention signal has text semantics and programmatic labels. Focus returns to the initiating object after a dialog or Intervention response. Long-running operations expose cancellation only when the backend operation supports it; closing a panel never implies cancellation.

## Client module responsibilities

The Saki client object layer owns Projection caching, Intent overlays, invalidation, view addresses, and selection. UI components receive data and actions through props and subscribe to immutable snapshots; they do not contain synchronization, retry, permission, or budget decisions. Frame-driven updates use the existing batched notification path, while immediate controlled-input echoes use the existing synchronous gesture path.

Saki registers the Work and Project pages through `main.surface`, their two primary navigation entries through `sidebar.primary.action`, and session or settings additions through existing typed slots. It consumes DSH conversation, Terminal, tool cards, settings, attachments, and file-opening capabilities through their published client services. Cross-domain value imports and a parallel global component registry are prohibited. A backend capability missing from the composed bundle produces an explicit unavailable Projection rather than removing controls through undocumented feature detection.

## Verification and remaining design work

Product-level Playwright flows boot the real Saki bundle, Host transport, control plane, Local Host adapter, temporary Git repositories, and controllable external Providers. They exercise Project registration, a beginner completing the Work cycle without technical controls, Project section switching without losing selection, Board refresh and conflict, manual and automatic launch, page-to-Session return with draft preservation, budget stop, reconnect, binding repair, intervention response, Diff-to-PR delivery, model authorization, and Generation Job output. Component tests cover only pure presentation and local interaction semantics; they do not replace the product flows.

Frontend implementation Issues may be split after low-fidelity interaction prototypes prove the flows above on desktop and on a constrained viewport without requiring simultaneous panes. Visual direction, density, layout, component styling, and branding remain open decisions. Generated concept images are discussion artifacts, not this contract's acceptance criteria.
