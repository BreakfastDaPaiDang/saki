# Saki 0.1.0 Web UI 接入基线

[English](0.1.0-web-ui-baseline.md) | 中文

本文以 DSH Web profile 为基准，确定 Saki 0.1.0 版本 Web 改动的范围。截图记录 Saki 要保留的组合，不是视觉验收用例或样式规范。壳层外观继续由 DSH 拥有。

## 保留 DSH 壳层

![DSH 空会话页面](../assets/baseline/2026-08-18/01-home-empty.png)

Saki 保留已交付的三栏 AppFrame、可收起侧边栏、会话页面、可选详情栏、设置对话框、主题系统、语言系统和 Session 导航。它不会替换 `root`、`sidebar` 或 `conversation` 占用项，也不会建立平行的 component registry。

| DSH 区域 | 保留的行为 | Saki 增量 |
| --- | --- | --- |
| AppFrame | 侧边栏、主栏、可选详情栏、缩放和响应式让步 | 一个可累加的主页面分发点；Conversation 继续作为 fallback |
| 侧边栏 | 品牌、New Session、Workspace 与 Session 浏览、收起行为、Settings | 两个主要入口：带 Attention 数量的「工作」与「项目」 |
| Conversation | Hero、composer、transcript、view tab、tool 展示和 pending interaction | 已关联 Session 上的 Project 与 Work Item 返回入口；可选的 Run evidence view |
| Settings | 对话框壳层、General、Models、Plugins、Agent Presets 和 Marketplace | 一个由 Saki 拥有的 Model Supply 分节；现有分节保留原职责 |
| 主题与语言 | DSH token、外观选择和已翻译 chrome | Saki 消费相同设施 |

## 新增两个顶层页面

0.1.0 只向 DSH 壳层增加两个 Saki 入口。Conversation、New Session 与 Settings 继续是继承的 DSH 页面，不计入 Saki 页面。Saki 页面可以打开一个上下文 drawer，但 Board、Agent Run、Git changes、model capacity、Attention 和 Terminal 不会同时常驻。

| 页面 | 复杂度与主要读者 | 主要任务 | 内部目的地 |
| --- | --- | --- | --- |
| 工作 | 简单；小白、偶尔参与者，或想要安静视图的操作者 | 跨已授权 Project 查看相关工作、提交需求、把 ready work 交给 Agent、回答问题和验收结果 | 用白话分为待开始、进行中、等你处理与最近结束；每项只提供一个下一步操作 |
| 项目 | 复杂；在一个已选择 Development Project 中工作的开发者、评审者或 Host Operator | 在不丢失执行历史的前提下规划、开发、观察、评审和交付所选 Project | 看板、里程碑、变更、会话与运行、追溯、项目设置 |

变更、会话与运行、追溯和项目设置是「项目」的内部区段，不是全局页面。主内容区每次只呈现活动区段。跨 Project 的 Attention 用白话出现在「工作」，Installation 级 Model Supply 仍是 Settings 分节。只有当一个区段拥有独立读者、导航生命周期或无法由「工作」与「项目」表达的跨 Project scope 时，未来才把它提升为顶层页面。

[K7（#51）](https://github.com/BreakfastDaPaiDang/saki/issues/51)是可编辑「项目设置」control 的唯一生产 owner，包括默认 Agent Profile、Automation Policy 与类型化预算、automatic-Done evidence 和同步配置。Resource Binding 与 GitHub mapping 只作为只读摘要出现，并链接到 K1 登记或 rebind flow 与 K3 mapping 或 repair flow。K6 在集成与恢复流程中消费已完成的该区段，不会在其他位置重新创建这些 control。

## 小白可操作的 My Work

My Work 是一种展示范围，不是较弱的事实来源或新的权限类别。它与专家页面消费相同的已授权 Projection，并提交相同的类型化 Intent。

默认页面只显示与当前 Principal 相关的工作，并分为待开始、进行中、等你处理和最近结束；这些是展示分组，不是 Work Item Status。每张卡片标明 Project、白话任务、当前 actor、最近确认时间和 My Work Projection 提供的推荐 Action Offer。Card Action Offer 包括交给 Agent、回答、审阅和打开。「提交需求」是页面操作，绝不占用条目的单一 card Action Offer。自动模式会把交给 Agent 替换为有归因的“Agent 正在处理”状态。等待验收的条目仍留在等你处理；Done 或 Canceled 条目绝不显示审阅或验收。

规范 GitHub Project status 仍可在详情中查看。branch、worktree、commit、Provider Account Profile、model route、budget reservation 和同步 evidence 只在用户打开技术详情或进入恢复操作后出现。隐藏这些事实绝不会允许 Principal 执行其无权执行的 operation。

组织账号出现前，0.1.0 版本可以先向 Host Operator 提供 My Work。以后 Principal preference 可以把它设为默认落地页，而无需改变它的 Projection 或 Intent 语义。

## 对现有页面的小改动

### 开始与导航

![已选择 Workspace 的 DSH New Session 页面](../assets/baseline/2026-08-18/06-new-session-workspace-selected.png)

New Session 和现有 Workspace picker 保持不变。Saki 在 New Session 下方增加「工作」与「项目」操作。激活任一操作时只替换主页面，侧边栏与 Settings 继续可用。返回 Session 时，按照现有 client store 恢复其 draft、所选 view 和 details 状态。

「工作」打开 My Work，并携带一个有文字语义的 Attention 数量。「项目」恢复最近选择的 Development Project 与内部区段；没有已选 Project 时则打开 Project selector。看板、里程碑、变更、会话与运行、追溯和项目设置保持为「项目」内部导航，不成为全局侧边栏入口。

### General 与 model settings

![DSH General settings](../assets/baseline/2026-08-18/02-settings-general.png)

General settings 保持不变。Saki 不会把 Project、GitHub、automation 或 organization control 加到这里。

![DSH model provider settings](../assets/baseline/2026-08-18/03-settings-models.png)

现有 Models 页面继续配置基础 provider connection。Saki 另行注册 Model Supply 分节，用于 account pool、authorization health、observed usage、routing、context policy 和 generation capacity。两页可以互相提供定位链接，但不会复制对方的字段。

### Plugins 与 Agent Presets

![DSH plugin settings](../assets/baseline/2026-08-18/04-settings-plugins.png)

![DSH Agent Presets](../assets/baseline/2026-08-18/08-settings-agent-presets.png)

Plugins、Marketplace 和 Agent Presets 保留现有导航与卡片结构。Saki 在适当位置作为已安装 plugin 配置出现。Project Agent Profile 引用 Agent Preset，不会 fork 或替换 preset editor。

### 可累加的壳层接口

DSH 壳层需要两个通用增量，Saki plugin 才能在不替换壳层的情况下提供独立页面：

- `main.surface` 是 AppFrame 主栏中渲染的 root scope chain slot。它的 fallback 渲染现有 `conversation` slot。选中的 Saki address 会激活 Saki entry；DSH package 不导入 Saki 类型。
- `sidebar.primary.action` 是 New Session 下方、Workspace browser 上方的 root scope list slot。这里承载日常产品目的地，因此 Saki 在此贡献「工作」与「项目」入口，侧边栏继续拥有它们的几何和收起呈现。它不同于现有 `sidebar.footer.action`；后者继续位于 Settings 旁边的底部区域，用于实用扩展。

`packages/saki/web-ui` 通过自身的小型 navigation interface 拥有 Saki 页面选择和 `SakiViewAddress` 持久化。它使用现有 `conversation.session.header.actions`、`conversation.view`、`settings.section` 和 `shell.overlay` slot，分别提供 Session context、Run evidence、Model Supply settings 和瞬时全局提示。`shell.overlay` 绝不会承载完整 Saki 页面。

## 0.1.0 排除项

0.1.0 不增加第三个 Saki 顶层页面、不重新设计继承的 Conversation 首页、不替换 DSH 侧边栏、不嵌入 IDE、不要求常驻操作者驾驶舱，也不把 provider 配置与日常工作合并。首个实现会先证明「工作」「项目」和继承 DSH 页面之间的导航、小白完成一次工作闭环、Session 与 Project 状态保留，以及两个可累加壳层接口，然后才扩大视觉改造。
