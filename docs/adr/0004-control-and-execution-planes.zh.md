# 分离控制面与执行面

[English](0004-control-and-execution-planes.md) | 中文

Saki 通过逻辑上的控制面与执行面分离产品决策和资源执行。控制面拥有 Project 意图、策略、路由、指派与持久投影；执行面拥有 Host 本地资源访问，并通过 DSH 完成受限工作。0.1.0 把两个面放在同一进程和仓库中，但通过 Execution 接口连接它们。

## 考虑过的方案

允许产品 View 和编排逻辑直接调用本地 Git、文件、进程、凭据和 Session 初期更简单，但会让远程 Host、迁移、恢复和资源归属逻辑散落到每个调用方。立即拆分网络服务则会在第二种执行实现出现前引入传输、部署和失败模式。逻辑分离保留当前的单一实现，并允许远程执行成为现实时增加网络适配器。

## 影响

控制面发送标识 Project、触发来源、Profile 版本、资源需求、限制和授权的执行请求。执行面回报带来源的状态事件、交互请求、结果和 Outcome Evidence，而不直接改写控制面投影。Host 路径、活资源句柄和凭据内容留在执行面；断开连接时只能继续先前已指派的工作或明确委派的离线策略，本地缓冲的事实在恢复连接后对账。
